# FE-TestForge

> Frontend Test Forge — テスト設計の判断から実装・CI運用までを鍛造するスキルパッケージ

フロントエンドのテストを「分類 → 戦略選定 → 設計判断 → 実装 → CI/安定化」まで
一貫して支援するスキルパッケージ。各スキルは独立した `SKILL.md` を持ち、
HELIX の skill-radar(FTS5)に個別登録できる粒度に分割している。

前提とするツールスタックは 2026 年時点の標準構成(`04-tooling` 参照)。

## 使い方(標準の流れ)

```
[理解]   01-taxonomy        … 粒度と観点の2軸を理解する
   ↓
[戦略]   02-strategy-selection … コードベース特性から戦略を1つ選ぶ
   ↓
[設計]   03-test-design     … 対象ごとに「何を/どの粒度で/どう配置」を判断
   ↓
[基盤]   04-tooling         … ツールと初期設定を確定
   ↓
[実装]   05〜10             … 設計結果に応じて該当スキルで実装
   ↓
[運用]   11-ci-flake        … CI に載せ、安定運用する
```

## 2026 年基準のツールスタック要約

詳細・選定根拠は `04-tooling`。要点のみ:

- ユニット/統合テストランナー: 新規は **Vitest**、レガシー/React Native は **Jest 30**
- DOM 操作・ユーザー視点検証: **Testing Library** + **@testing-library/user-event**
- API モック: **MSW(Mock Service Worker) 2.0**(ネットワーク層で傍受)
- コンポーネント隔離・ドキュメント・統合テスト: **Storybook 9**(Vitest addon / portable stories)
- E2E・コンポーネントテスト(CT)・VRT: **Playwright**
- アクセシビリティ: **axe-core**(Vitest 系は `vitest-axe`/`jest-axe`、Playwright は `@axe-core/playwright`)

## HELIX 統合ポイント(要・自プロジェクト確認)

> V字レベル(L1〜L4)・5層ゲートの正規定義に合わせて確定する(勝手な機能追加はしない方針)。

- 各スキルを skill-radar(FTS5)へ個別登録(`keywords` / `description` 整備済み)。
- テスト粒度(ユニット/統合/E2E)を V字レベルへマッピング(対応は HELIX 側定義に従う)。
- 各実装スキルの「パス条件」を 5 層ゲートのどのゲートに紐付けるか定義する。
- 「判断」スキル(02/03)は思考側(Claude Code)、「実装」スキル(05〜10)は実装側
  (Codex CLI)に割り当てる二軸運用に載せる。
