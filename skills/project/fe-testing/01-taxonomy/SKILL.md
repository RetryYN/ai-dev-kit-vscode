# テスト分類基盤(粒度 × 観点)

## 大原則

「〇〇テスト」という用語は、性質の異なる2軸が混在している。**最初にこの2軸を分離する。**

| 軸 | 問い | 該当する用語 |
| --- | --- | --- |
| 粒度(対象範囲) | 「何を」テストするか | ユニット / インテグレーション / E2E |
| 観点(検証内容) | 「どの性質を」テストするか | ロジック / インタラクション / スナップショット / VRT / a11y / パフォーマンス / クロスブラウザ |

- 「手動テスト」は粒度でも観点でもなく **方法** の軸(対義は自動テスト)。混同しない。
- 2軸は **掛け合わせ可能**。「ユニット粒度で VRT」も「E2E 粒度で VRT」も成立する。
- ただし全セルを埋めるのは非現実的。`03-test-design` の判断で取捨選択する。

---

## 粒度の定義

| 粒度 | 定義 | フロントエンドでの例 |
| --- | --- | --- |
| ユニット | 依存を持たない、またはモック化された単一ユニットを検証 | 独立した関数 / カスタムフック / 表示専用コンポーネント |
| インテグレーション | 複数ユニットが統合されて動作するかを検証 | フォーム+バリデーション+状態、複合 UI、API 連動 UI |
| E2E | フロントからバックエンド・インフラまで実ユーザー操作と同等の環境で検証 | ログイン〜決済の操作フロー |

> 定義は唯一に定まらない。チーム内で自分たちの定義を一度合意し、文書化すること。

### 粒度別の特性(★が多いほど良い)

| 粒度 | リアリティ | 安定性 | 速度 | 作成コストの低さ | 維持コストの低さ |
| --- | --- | --- | --- | --- | --- |
| E2E | ★★★ | ★☆☆ | ★☆☆ | ★☆☆ | ★☆☆ |
| インテグレーション | ★★☆ | ★★☆ | ★★☆ | ★★☆ | ★★☆ |
| ユニット | ★☆☆ | ★★★ | ★★★ | ★★★ | ★★★ |

**含意:** E2E は最も本物に近いが壊れやすく遅く高コスト。ユニットは逆。
インテグレーションは中間でバランス点になりやすい。

> 2026 年の補足: Storybook(Vitest addon)や Playwright のコンポーネントテスト(CT)により、
> 「実ブラウザ × 隔離」という従来ユニットと E2E の間に空いていた帯域が埋まりつつある。
> これにより「複合 UI を実ブラウザで隔離テストする」選択肢が現実的になった(詳細は `04-tooling`)。

## 観点の定義

| 観点 | 検証する性質 | 実装スキル |
| --- | --- | --- |
| ロジック | 入力に対する出力・状態遷移が仕様通りか | `05-unit-logic` |
| インタラクション | 操作(クリック/入力/フォーカス)に対する挙動 | `06-interaction` |
| スナップショット | 出力(DOM/シリアライズ)が前回から変化していないか | `05` / `06` |
| ビジュアルリグレッション(VRT) | 描画結果(見た目)が前回から変化していないか | `08-visual-regression` |
| アクセシビリティ(a11y) | ロール/ラベル/コントラスト/キーボード操作が規格を満たすか | `09-accessibility` |
| パフォーマンス | 描画時間・バンドル・応答が基準内か | `10` / `11` |
| クロスブラウザ | 複数ブラウザ/デバイスで同等に動作するか | `10-e2e` |
