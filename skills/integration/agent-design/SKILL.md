# Agent Design スキル

## このスキル群の位置づけ

AIエージェント設計における **判断軸の集合**。各判断軸を独立 reference として分離し、本 SKILL.md が全体マップと参照順序を提供する。

スキルとは判断軸の集合であり、型・骨格とは直交する別資産。**型は「どう構成するか」を定義し、スキルは「どう判断するか」を定義する**。両者が揃って初めて設計が成立する。

## 適用タイミング

- 新規 AIエージェント (LLM 駆動) の設計を始める前
- 既存エージェントの責務・スキーマ・後段ロジックを整理する時
- 「自由型」「自然言語に任せる」設計を構造化したい時
- プロンプト・スキーマ・後段検証のどこに何を置くか迷った時

## 還元式

すべての設計対象は以下の還元式に従う。

```
型 = 要素定義 + フレーム化
```

PREP・SDS・MECE・ワークフロー・スキーマ等、設計で扱うすべての構造は要素とフレームの組み合わせに還元される。組み合わせ空間は無限であり、新しい型は既存要素の組み換え (リフレーミング・具体化・抽象化・合成) から生まれる。

## 3 レイヤー構造

エージェント設計は 3 つのレイヤーで構成され、各レイヤーが下位を構成要素として持つ入れ子構造になる。

```
レイヤー3: ワークフロー = タスクの連鎖 (順序固定・不可逆)
    ↓ 各ノードを開けると
レイヤー2: タスク = フレームワークで構成 (入出力契約付き処理単位)
    ↓ 各タスクの内部を開けると
レイヤー1: フレームワーク = 要素 + フレーム化
    ↓ さらに分解すると
レイヤー0: 要素・フレーム (最小単位)
```

各レイヤーで「要素 + フレーム化」という同じ還元式が再帰的に適用される。

## 縛りの階層

完全な決定論化は不可能。設計が縛れるのは以下の 3 階層であり、内側ほど確率に委ねる範囲が増える。

| 層 | 縛れるもの | 縛り方 | 性質 |
|---|---|---|---|
| 構造 | フィールド・型・骨格 | スキーマ・骨格定義 | 決定論 |
| 表層 | 文字数・語彙・トーン・書式 | 特徴定義・制約記述 | 半決定論 |
| 内容 | 文章の意味・表現 | Few-shot・思考指定 | 確率的誘導 |

設計者の仕事は「自由を許容する」ことではなく、**どの階層に型を置き、どの階層に自由度を残すかを意識的に決めること**。

## 設計フロー全体像

```
タスク受領
    ↓
[01] 要素とフレームを定義
    ↓
[02] 骨格を選択 or 新規定義
    ↓
[03] フレームワークかワークフローかを判定
    ├── フレームワーク → [05][06] へ
    └── ワークフロー → タスク分解 → 各タスクで [04]
        ↓
[04] 各タスクのパッチ/フル生成を判定
    ↓
[05] 思考の指定を書く
    ↓
[06] 出力の指定を書く
    ↓
[07] スキーマを導出
    ↓
[08] 前段で生成制約として注入
    ↓
[10] 縛りの階層を確認
    ↓
[11] 効果と配置を最終調整
    ↓
[09] 後段の責務を限定して実装
```

## 中核原則 (全 reference 共通)

- **前段で絞り、後段は正規化に徹する**: 確率で足りる制約は前段、決定論が必要な制約は後段
- **制御点は思考と出力の 2 軸のみ**: 前段で打てる手はこの 2 箇所しか存在しない
- **骨格起点**: スキーマも思考指定も後段検証も、すべて骨格から派生する
- **自由型を認めない**: 完全な自由は存在せず、自然言語自体が文法という型に従っている
- **スキルと型は直交資産**: 判断軸 (スキル) と構造 (型) は別管理する

## アンチパターン (全レベル共通)

- 要素・フレームを定義せずに骨格やスキーマから書き始めている
- 骨格を定義せずにスキーマや思考指定から書き始めている
- 「自由型」を許容している
- 後段でリトライ・フィルタ・修正を積み重ねている
- スキルと型を混同して管理している
- 縛りの階層を意識せず、すべて同じレベルで扱っている
- 各判断軸を順序を無視して適用している (依存関係の無視)
