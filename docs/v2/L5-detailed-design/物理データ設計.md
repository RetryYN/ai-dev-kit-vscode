# 物理データ設計

## 1. 目的と境界

本書は `helix.db` を中心とした HELIX-workflows V2 の物理データ設計を定義する。L4 データ設計で固定した論理領域を、SQLite テーブル、index、FK、migration へ展開する。個別 query の実装詳細や集計 SQL の最適化は L6/L7 に送る。

## 2. 入力とトレース

| 区分 | 入力 | 本書での使い方 |
|---|---|---|
| L4 方式 | `docs/v2/L4-basic-design/方式設計.md` | SQLite を runtime state 保存先に限定する方針の具体化 |
| L4 機能構成 | `docs/v2/L4-basic-design/機能構成設計.md` | PLAN/Audit/Trace/Workspace の領域分割 |
| L4 データ | `docs/v2/L4-basic-design/データ設計.md` | 論理エンティティを物理テーブルへ展開 |
| L4 外部 IF | `docs/v2/L4-basic-design/外部IF設計.md` | HTTP route/hook から参照される保存先を特定 |
| 実装 | `cli/lib/helix_db.py`, `cli/lib/migrations/v35_plan_registry.py`, `cli/lib/http_api/routes/*.py` | 実際の DDL、index、FK、upsert 利用箇所を確定 |

## 3. 物理保存方針

| 項目 | 現行実装 |
|---|---|
| DB | SQLite (`.helix/helix.db`) |
| journal mode | `WAL` |
| busy timeout | `5000ms` |
| schema version | `CURRENT_SCHEMA_VERSION = 36` |
| schema source | `cli/lib/helix_db.py` + additive migrations `v31`〜`v35` |
| lock | `file_lock` による project/home scope 排他 |

- ベース schema は `helix_db.py` に集約する
- 破壊的変更は既定で許容せず、additive migration を優先する
- `schema_version` は migration 適用済み version を記録する
- workspace 系 state は `workspace_registry` に切り出し、main repo と worktree の混線を防ぐ

## 4. 領域別テーブル配置

| 領域 | 代表テーブル | 用途 |
|---|---|---|
| Plan Governance | `plan_registry`, `plan_dependencies`, `plan_agent_slots`, `plan_references`, `plan_generates`, `sprint_progress` | PLAN の索引、依存、生成物、進捗 |
| Execution / Audit | `automation_runs`, `audit_log`, `session_telemetry`, `gate_runs`, `plan_reviews`, `interrupts` | 実行、監査、review、telemetry |
| Trace Catalog | `code_index`, `entries`, `links`, `contract_entries`, `code_edges`, `test_design_entries`, `design_review` | artifact 関係、契約、test-design 対応 |
| Workspace / Continuity | `workspace_registry`, `sessions`, `locks`, `jobs`, `schedules` | セッション継続、worktree、排他、非同期実行 |
| Requirements / Quality | `requirements`, `req_impl_map`, `req_test_map`, `accuracy_score`, `verify_runs` | 要件 trace、検証メトリクス |

## 5. 代表 DDL

### 5.1 Plan Governance

```sql
CREATE TABLE IF NOT EXISTS plan_registry (
    plan_id TEXT PRIMARY KEY,
    title TEXT NOT NULL,
    kind TEXT NOT NULL,
    layer TEXT NOT NULL,
    drive TEXT NOT NULL,
    status TEXT NOT NULL DEFAULT 'draft',
    size TEXT,
    owner TEXT,
    related_adr TEXT,
    frontmatter_json TEXT NOT NULL,
    doc_path TEXT NOT NULL,
    created_at TEXT NOT NULL DEFAULT (datetime('now')),
    updated_at TEXT NOT NULL DEFAULT (datetime('now'))
);
CREATE INDEX IF NOT EXISTS idx_plan_registry_status ON plan_registry(status);
CREATE INDEX IF NOT EXISTS idx_plan_registry_kind ON plan_registry(kind);

CREATE TABLE IF NOT EXISTS plan_dependencies (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    plan_id TEXT NOT NULL,
    dep_type TEXT NOT NULL,
    dep_plan_id TEXT NOT NULL,
    created_at TEXT NOT NULL DEFAULT (datetime('now')),
    FOREIGN KEY (plan_id) REFERENCES plan_registry(plan_id) ON DELETE CASCADE,
    UNIQUE (plan_id, dep_type, dep_plan_id)
);

CREATE TABLE IF NOT EXISTS sprint_progress (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    plan_id TEXT NOT NULL,
    sprint_id TEXT NOT NULL,
    status TEXT NOT NULL DEFAULT 'not_started',
    completed_files TEXT,
    blocker_note TEXT,
    session_id TEXT,
    timestamp TEXT NOT NULL DEFAULT (datetime('now')),
    FOREIGN KEY (plan_id) REFERENCES plan_registry(plan_id) ON DELETE CASCADE,
    UNIQUE (plan_id, sprint_id)
);
```

### 5.2 Automation / Audit

```sql
CREATE TABLE IF NOT EXISTS automation_runs (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    run_kind TEXT NOT NULL,
    plan_id TEXT,
    trigger_actor TEXT NOT NULL,
    started_at TEXT NOT NULL DEFAULT (datetime('now')),
    ended_at TEXT,
    status TEXT NOT NULL DEFAULT 'pending'
        CHECK(status IN ('pending','running','completed','failed','cancelled')),
    exit_code INTEGER,
    summary TEXT,
    retry_count INTEGER NOT NULL DEFAULT 0,
    max_retries INTEGER NOT NULL DEFAULT 0,
    last_error TEXT
);

CREATE TABLE IF NOT EXISTS audit_log (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    audit_kind TEXT NOT NULL,
    actor TEXT NOT NULL,
    run_id INTEGER,
    payload TEXT NOT NULL,
    recorded_at TEXT NOT NULL DEFAULT (datetime('now')),
    FOREIGN KEY (run_id) REFERENCES automation_runs(id)
);

CREATE TABLE IF NOT EXISTS session_telemetry (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    session_id TEXT NOT NULL UNIQUE,
    started_at TEXT NOT NULL DEFAULT (datetime('now')),
    ended_at TEXT,
    actor TEXT NOT NULL,
    related_plan_id TEXT,
    tool_uses_count INTEGER NOT NULL DEFAULT 0,
    tokens_total INTEGER NOT NULL DEFAULT 0,
    cost_usd REAL NOT NULL DEFAULT 0.0,
    last_updated_at TEXT NOT NULL DEFAULT (datetime('now'))
);
```

### 5.3 Trace Catalog

```sql
CREATE TABLE IF NOT EXISTS code_index (
  id TEXT PRIMARY KEY,
  domain TEXT NOT NULL,
  summary TEXT NOT NULL,
  path TEXT NOT NULL,
  line_no INTEGER NOT NULL,
  symbol_line INTEGER NOT NULL DEFAULT 0,
  since TEXT,
  related TEXT,
  source_hash TEXT,
  bucket TEXT NOT NULL DEFAULT 'coverage_eligible',
  updated_at DATETIME
);

CREATE TABLE IF NOT EXISTS entries (
    id TEXT PRIMARY KEY,
    axis TEXT NOT NULL
        CHECK(axis IN ('design','plan','code','schema','test','review','evidence')),
    stack TEXT,
    lifecycle TEXT NOT NULL
        CHECK(lifecycle IN ('initial','addition','modification','migration','deprecation','removed')),
    parent_entry_id TEXT,
    sprint_id TEXT,
    agent_actor TEXT,
    ref TEXT NOT NULL,
    version TEXT,
    metadata TEXT,
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    updated_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    FOREIGN KEY (parent_entry_id) REFERENCES entries(id) ON DELETE SET NULL
);

CREATE TABLE IF NOT EXISTS links (
    from_id TEXT NOT NULL,
    to_id TEXT NOT NULL,
    kind TEXT NOT NULL
        CHECK(kind IN ('uses','covers','reviews','implements','derives_from','supersedes')),
    metadata TEXT,
    PRIMARY KEY (from_id, to_id, kind),
    FOREIGN KEY (from_id) REFERENCES entries(id) ON DELETE CASCADE,
    FOREIGN KEY (to_id) REFERENCES entries(id) ON DELETE CASCADE
);

CREATE TABLE IF NOT EXISTS test_design_entries (
    id INTEGER PRIMARY KEY,
    plan_id TEXT NOT NULL,
    acceptance_key TEXT NOT NULL,
    contract_id INTEGER,
    test_level TEXT NOT NULL CHECK (test_level IN
        ('operational','acceptance','system_integration','integration','unit')),
    paired_design_level TEXT NOT NULL CHECK (paired_design_level IN
        ('planning','requirement','architecture','detailed','functional')),
    pyramid_layer TEXT NOT NULL,
    test_target TEXT,
    expected_status TEXT NOT NULL,
    created_at TEXT NOT NULL,
    UNIQUE (plan_id, acceptance_key, test_level)
);
```

## 6. index 戦略

| 対象 | index | 目的 |
|---|---|---|
| `plan_registry` | `status`, `kind` | 状態別の PLAN 一覧取得 |
| `plan_dependencies` | `plan_id`, `dep_plan_id` | requires/blocks の双方向検索 |
| `automation_runs` | `run_kind`, `status`, `started_at` | trigger 種別・進行中 run の抽出 |
| `audit_log` | `audit_kind`, `actor`, `run_id`, `recorded_at` | 監査トレースと時系列取得 |
| `session_telemetry` | `actor`, `started_at`, `related_plan_id` | role/model 別集計 |
| `code_index` | `domain`, `summary`, `path`, `bucket` | code search と coverage bucket 参照 |
| `entries` / `links` | `axis`, `stack`, `sprint_id`, `agent_actor`, `kind` | artifact trace とスコープ集計 |
| `workspace_registry` | `status`, `task_id` | active workspace 検索 |
| `locks` | `expires_at` partial index | lock timeout 清掃 |

## 7. FK / cascade 方針

| 子テーブル | 親テーブル | 方針 |
|---|---|---|
| `plan_dependencies`, `plan_agent_slots`, `plan_references`, `plan_generates`, `sprint_progress` | `plan_registry` | `ON DELETE CASCADE`。PLAN 削除時に従属索引を掃除する |
| `audit_log` | `automation_runs` | FK のみ。監査を run に紐付ける |
| `entries.parent_entry_id` | `entries.id` | `ON DELETE SET NULL`。親削除でも子 artifact の孤立を許容する |
| `links.from_id`, `links.to_id` | `entries.id` | `ON DELETE CASCADE`。trace link を孤立させない |
| `workspace_registry` | 直接 FK なし | git/worktree 実体との同期を優先し、論理参照は `task_id`/`base_sha` で追う |

## 8. migration / rollback

```text
1. 起動時に schema_version を確認する
2. 未適用 version があれば additive migration を順に適用する
3. 各 migration は CREATE TABLE/INDEX と必要最小限の ALTER を行う
4. 適用後に schema_version へ version を記録する
5. destructive change が必要なら本番影響として人間承認へエスカレーションする
6. rollback は DB backup と schema_version を基準に人手で戻す
```

## 9. セキュリティ / 運用上の制約

- `agent_slots` と `harness_check_events` は append-only trigger を持つ
- 認証情報そのものを保持する専用 column は現行 schema にはない
- HTTP automation からの write は localhost + bearer token を前提とする
- DB lock と workspace registry を併用し、並列実行時の衝突を抑止する
